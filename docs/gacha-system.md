# 招贤抽卡系统 + 数据配置化 设计

> 子文档，详细设计见此；全局进度表见 `../DESIGN.md`。对应需求 **R8（重定义）**。
> R8 将"固定商店塔防"改造为"招贤抽卡 roguelike 塔防"。

---

## 一、核心玩法转变

| 旧（R1~R7） | 新（R8） |
|---|---|
| 商店点武将直接造塔，可重复造同名塔 | 取消商店；**招贤**随机获取武将 |
| 军粮分别花在造塔/升级 | 军粮统一花在**招贤（刷新）+ 招募（部署/升级）** |
| 同名塔可多座 | **武将唯一部署**：每个武将只有一座塔，重复抽到则升级 |
| 武将固定 4 个 | 武将池扩到约 8 个，可继续扩展 |

### 经济模型（自走棋式两层花费）

| 花费 | 作用 | 规则 |
|---|---|---|
| ① 招贤（刷新） | 控制抽取频率 | **递增**：本关内每次刷新更贵；过关重置 |
| ② 招募（部署/升级） | 控制可用武将强度 | 按武将**星级**定价；抽到已有 → 花此费升级 |

**一次操作流程**：点「招贤」付递增刷新费 → 弹出 **3 个候选** → 选 1 个付其招募费 → 新武将进入待部署（点地图空地放下）/ 已有武将升级。满级武将从招贤池排除。

军粮唯一来源仍是击杀掉落，形成闭环：杀敌 → 军粮 → 招贤/招募 → 更强 → 杀更多。

## 二、数据配置化（R8-1，地基）

新建 **`data.js`**（在 sprites.js / game.js 之前加载），集中导出 `window.GameData`：

```
GameData = { RARITY, ARCHETYPES, HEROES, BONDS, ENEMY_TYPES, LEVELS }
```

game.js 不再自带这些 const，改从 `GameData` 读取。**扩展约定**：
- 加武将 = `HEROES` 加一项 + `sprites.js` 加一个画法（或在 `SPRITE_ASSETS` 填图片）。
- 加羁绊 = `BONDS` 加一项。
- 加关卡 = `LEVELS` 加一项。

### Schema

```
RARITY = {
  1: { star:"★",   deployCost:40,  drawWeight:10 },
  2: { star:"★★",  deployCost:70,  drawWeight:5  },
  3: { star:"★★★", deployCost:110, drawWeight:2  },
}

HERO = {
  id, name, faction, arch,        // arch: archer|spear|strategist
  rarity,                          // 1|2|3 → 决定招募费与抽取权重
  color,                           // 程序化形象主色
  maxLevel: 3,                     // 满级 → 招贤池排除
  // 可选：同兵种内差异化（默认 1）
  dmgMul, rangeMul, rateMul, splashOverride,
}

BOND = { id, name, heroes:[id...], effect:{ dmgMul?, rateMul? }, desc }
```

升级成本（抽到已有）：`round(deployCost * 0.7 * currentLevel)`。

## 五、招贤抽卡系统（R8-4，替换商店）

- UI：右侧栏「布阵」改为「**招贤馆**」：一个「招贤（费用）」按钮 + 招募候选区。
- 点招贤：扣递增刷新费 → 从池中按权重随机 3 个（排除满级、可含已有用于升级）→ 显示 3 张候选卡（名/星级/招募费/兵种）。
- 选候选：扣招募费。若为新武将 → 进入待部署（点空地放下，沿用现有 hover/place）；若已有 → 直接升级该武将。
- 招贤池 = 未满级武将（新武将 + 未满级的已部署武将）。全满级则招贤按钮置灰。
- 刷新费：本关 `30 → 45 → 60 …`（+15），`startLevel` 重置。
- 移除旧「点商店造塔」「U 升级」交互（升级改由抽到重复触发）；保留卖塔（撤将）但返还改为"返还招募投入的 50%"。

## 六、图鉴页面（R8-5）

- 主菜单加「图鉴」按钮 → 弹出图鉴遮罩。
- 两区：**武将图鉴**（名/阵营/兵种/星级/招募费/特点）、**羁绊图鉴**（名/所需武将/效果）。
- 数据直接来自 `GameData`，新增武将/羁绊自动出现在图鉴，无需改图鉴代码。

## 七、难度递增 + 经济平衡（R8-6）

- 难度整体上调并更明确递增（关卡波次强度、敌人数量/血量缩放逐关增大）。
- 围绕两层花费用**页内无头模拟器**重新调平：击杀奖励、起始军粮、刷新费曲线、招募费、升级费，使

  - 难度曲线：第1关教学、中段稳、末关险胜。

## 九、验收标准

1. 招贤出 3 候选、扣递增刷新费；选取扣招募费；新武将可部署、重复触发升级、满级出池。
2. 武将唯一部署（不能重复放同名）。
3. 8 武将形象互相可区分；3 羁绊可正确激活并生效。
4. 图鉴正确列出全部武将与羁绊，新增数据自动出现。
5. 数据全部来自 `data.js`，加武将/羁绊只改配置（+形象）。
6. 难度逐关递增；模拟器验证可过关但有压力。
7. 单局重置：过关/重开后武将与刷新费归零。
8. 无 console 报错。
