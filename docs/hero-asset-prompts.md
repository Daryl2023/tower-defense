# 武将资产 AI 生图提示词（V2Fun.art · 路线 A）

> 子文档，供 R6 美术资源替换使用；全局进度见 `../DESIGN.md`。
> 风格路线：**Q 版塔防风**（王者荣耀风，2.5 头身）；工具：**V2Fun.art AI 绘画**。
> 每个武将分 3 条提示词：精灵表 → 立绘 → 技能图标。建议按顺序生成，用图生图保持同将一致。
>
> **⚠️ 透明背景是硬性要求**：战场武将由 Canvas 绘制，**CSS 无法去掉背景**。若 PNG 无真透明通道、或把棋盘格画进图里，部署到地图后会看到灰白方格底——关羽首版即因此返工。

## 一、工具设置

| 项 | 建议 |
|---|---|
| 模块 | **AI 绘画 → 文生图**（精灵表/图标）；**图生图**（立绘，参考该将待机帧） |
| 模型 | **nanobanana 系列** 或 **qwen-image 系列**（动漫/游戏资产风） |
| 比例 | 风格样张 1:1；精灵表 **2:1**（2行4列，如 2048×1024）；单帧 1:1；立绘 3:4；图标 1:1 |
| **导出格式** | **PNG-32 / RGBA，带 Alpha 通道**；禁止 JPEG、禁止「仅 RGB 无透明」的 PNG |
| 注意 | **不要**使用「T-pose / 3D 生成参考图」；提示词优化后检查并删除 3D/PBR/T-pose 等词 |

## 二、透明背景与分格规范（必读）

> 实战问题汇总：
> - **关羽**：AI 导出为 RGB PNG（无 Alpha），约 74% 像素是灰白棋盘格/白底被**画进图里**；战场上出现明显方格底（**图片问题，非 CSS**）。
> - **赵云**：棋盘格有**深灰 ~98 + 浅灰 ~144 两色**，只去一种会残留方格；已用灰度阈值 + 加载时自动去底。
> - **刘备/关羽等**：同类风险，游戏加载时会自动尝试去底。
> - **串帧**：相邻格武器/披风越界，裁切时出现隔壁帧边角（可配 `frameInset` 缓解，但生成时应避免）。

### 2.1 透明背景（真 PNG Alpha，最高优先级）

| 要 | 不要 |
|---|---|
| **RGBA 真透明**：背景像素 Alpha=0，仅角色有像素 | 把棋盘格 / checkerboard **画成可见灰白格子** |
| 背景区域在预览里「透过去」看到下层 | 灰色 #c0c0c0、白色 #ffffff 实色铺底 |
| 导出 **PNG-32（RGBA）**，文件属性 `hasAlpha: yes` | JPEG（绝无透明） |
| 仅角色本体 + 可选脚下极淡光晕（占脚宽内） | 地面、场景、烟雾、渐变天空、整图白底 |

**每条精灵表 / 立绘 / 图标提示词末尾必附（可复制）：**
```text
【导出硬性要求】真透明PNG-32（RGBA alpha通道），背景像素必须完全透明（alpha=0），禁止把透明背景画成棋盘格/checkerboard/灰白相间格/灰底/白底/纯色底/地面/场景；仅保留角色与武器像素，文件导出须带透明通道
```

**V2Fun.art 生成时注意：**
1. 提示词里写清「真透明 / alpha 通道 / 禁止棋盘格」，不要只写「透明背景」四字（AI 易理解成画棋盘格示意）。
2. 下载后**用系统预览或 PS 打开**，把图拖到有色背景上：若仍见灰白格或白块 → **不合格，需重生成或抠图**。
3. 不合格时可用 PS「魔棒」去灰白格，或脚本按灰/白低饱和像素抠底，再存为 PNG-32。

**快速自检（终端，可选）：**
```bash
# macOS：hasAlpha 必须为 yes
sips -g hasAlpha assets/heroes/{id}/sheet.png
file assets/heroes/{id}/sheet.png   # 应含 RGBA，而非 RGB 或 JPEG
```

### 2.2 八帧完全分格（防裁切串帧）

| 要 | 不要 |
|---|---|
| 2 行 × 4 列，每格等大、对齐网格 | 8 帧挤在一行里互相重叠 |
| 角色居中占格内约 **65%~75%** | 武器/披风伸出到隔壁格 |
| 格与格之间 **≥15% 格宽的透明间隙** | 帧边缘贴死、肢体跨格 |
| 每帧脚底落在同一水平线 | 每帧比例/朝向不一致 |

**提示词必写一句：**
```text
8帧严格分格排列，每帧角色完全位于各自格子内不越界，格子之间留明显透明间隙，武器披风不得碰到相邻帧
```

### 2.3 推荐生成方式（二选一）

**方案 A（最稳）：8 张独立 PNG**

分 8 次生成，每次只出 1 帧，文件名 `idle` `run` `attack1`…，本地再拼成精灵表或直接逐帧配置。几乎不会串帧。

**方案 B：一张 2×4 精灵表**

比例建议 **2:1 横图**（如 2048×1024），先出待机单帧确认透明与画风，再按同提示词出整表；生成后用 PS/在线工具检查每格边界是否干净。

### 2.4 立绘 / 技能图标透明要求

立绘、技能图标与精灵表**同一套透明标准**（战场用精灵表，图鉴/招贤用立绘，均须真 RGBA）。

```text
【导出硬性要求】真透明PNG-32（RGBA），仅角色/图标本体有像素，无场景无地面无棋盘格无灰底白底；立绘脚下可有极淡光晕但不超过脚宽
```

图鉴与招贤卡的 `<img>` 已设 `background: transparent`，**但若 PNG 本身带灰白底，UI 上仍会露底**——根因仍是图片，不是 CSS。

### 2.5 游戏内自动去底（已接入 `sprites.js`）

AI 图仍带棋盘格时，游戏加载时会自动执行 `stripAICheckerboard`：

- 去除**低饱和中性灰**（约 RGB 85–158，覆盖暗格 ~96 与亮格 ~144）
- 去除纯白底（精灵表 ≥238，立绘 ≥250 以免误伤白袍）
- **保留**有色彩的盔甲/皮肤/特效（银甲约 ≥161 不会被误删）

仍建议在生成阶段尽量出真透明 PNG；自动去底是兜底，极浅灰抗锯齿边可能残留细线。

若某将白袍/白甲被误删，可在 `IMAGE_OVERRIDES` 为该将设 `stripBg: false` 后改用手动抠图。

### 2.6 导出验收清单（每张图必做）

| # | 检查项 | 合格标准 |
|---|--------|----------|
| 1 | 文件格式 | PNG，**RGBA**，非 JPEG、非 RGB-only |
| 2 | Alpha 通道 | `sips -g hasAlpha` → **yes** |
| 3 | 视觉检查 | 拖到绿色/深色背景上，角色外**无**灰白棋盘格、无白块 |
| 4 | 战场实测 | 进游戏部署该将，地图格子上**仅见角色**，无方格底 |
| 5 | 串帧（精灵表） | 放大看每格边界，邻格无武器/披风伸入 |

## 五、推荐工作流

1. 生成 **风格圣经**（§三）→ 确认画风与透明底
2. 先生成该将 **待机单帧**（1:1）→ 确认无棋盘格、角色不越界
3. 按 **§二方案 A 或 B** 生成 **8 帧精灵**
4. 图生图生成 **立绘**（融合强度 0.5~0.6，同样真透明底）
5. 生成 **技能图标**（各自独立方格，格间留隙）
6. 用看图工具检查每格边界 → 导出 PNG 至 `assets/`
7. 在 `sprites.js` 的 `IMAGE_OVERRIDES` 配置路径；若整表仍轻微串帧可设 `frameInset: 0.08`

## 八、生成后接入游戏

图片裁切完成后放入 `assets/`，在 `sprites.js` 的 `IMAGE_OVERRIDES` 填入路径即可切换，详见 `art-system.md` §2.3。

| 资产类型 | 建议文件名 | 配置项 |
|----------|-----------|--------|
| 精灵表（2×4 整表或 8 张单帧） | `assets/heroes/{id}/sheet.png` | `img`, `cols`, `rows`, `frameW`, `frameH` |
| 立绘 | `assets/heroes/{id}/portrait.png` | `portrait` |
| 技能图标 | `assets/heroes/{id}/icons.png` | `icons`（待 R9 UI） |
| 裁切余量（整表轻微串帧时） | — | `frameInset: 0.08`（每格四边内缩 8%） |

**生成后自检清单：**
1. `file` / `sips -g hasAlpha` 确认为 **PNG RGBA**，`hasAlpha: yes`（非 JPEG、非 RGB-only）
2. 拖到有色背景上目视：角色外无灰白棋盘格、无白块
3. 放大检查每格边界，邻格无武器/披风伸入
4. 游戏中部署该将：地图上**无方格底**（战场走 Canvas，CSS 救不了假透明）
5. 攻击/待机切换时无「边角料」；轻微串帧可设 `frameInset: 0.08~0.1`
