# 体验改版：可读性 / 武将府 / 选将详情 / 关卡差异化（R25）

> 对应试玩反馈：关卡体验同质化、武将形象观感弱、图鉴与养成割裂、入关选将信息不足。
> 全局进度表仍集中在 `DESIGN.md`，本文档维护本模块详细设计。

## 1. 目标

R25 先解决玩家决策链路不清的问题：玩家在入关前要知道“这一关需要什么”，在选将时要知道“这个武将是什么类型”，在查看武将时要同时看到“属性、碎片、升级、被动、羁绊”。

本期不优先扩内容数量，而是提升已有内容的可读性和差异化。

## 2. 子任务

### R25-1 武将府：合并图鉴与养成

现状图鉴与养成分为两个入口，玩家查看属性、碎片、升级成本、羁绊时需要来回切换。

设计：
- 主界面与关卡选择只保留一个入口：`武将府`。
- 武将府列表展示头像、姓名、星级、兵种、定位标签、Lv、碎片、招募/升级状态。
- 武将详情页展示完整属性、永久养成、招募/升级按钮、被动技能、参与羁绊。
- 旧“羁绊总览”可留在武将府列表页底部，但具体羁绊也必须出现在对应武将详情中。

涉及文件：
- `index.html`：入口按钮与场景文案。
- `game.js`：合并 `openCodex` / `renderTrainList` 的信息流；详情页加入招募/升级操作。
- `style.css`：武将府列表、标签、详情操作按钮样式。

验收标准：
- UI 上不再出现分离的“养成”和“图鉴”两个主入口。
- 进入武将府后，点任一武将可同时查看属性、碎片、升级/招募、被动、参与羁绊。
- 在详情页升级/招募后，Lv/碎片/按钮状态即时刷新并持久化。

### R25-2 选将详情与兵种/定位展示

现状选将页信息不足，只能大致看到头像、名字、等级、被动，不利于入关前做阵容判断。

设计：
- 选将卡展示兵种标签（弓/枪/谋）与定位标签（输出/范围/控制/经济/光环/破甲/收割等）。
- 点击卡片主体打开武将详情面板，查看属性、被动、羁绊。
- 点击勾选按钮才加入/移出阵容，避免“想看详情却误改阵容”。

涉及文件：
- `index.html`：选将场景增加详情面板。
- `game.js`：选将卡点击逻辑拆分为“查看详情”和“切换出战”。
- `style.css`：选将网格与详情面板布局、标签与勾选按钮。

验收标准：
- 选将页每张卡能看出兵种与定位。
- 点击卡片主体展示该武将详情；点击勾选按钮切换出战。
- 出战人数限制与存档逻辑保持不变。

### R25-3 关卡差异化（首批已落地：敌情提示 + 轻规则）

现状关卡虽有敌人和 Boss 变化，但玩家体感策略差别不够明显。

首批落地 A：敌情提示
- 每关增加 `tags / threats / recommends`，在选将页展示“敌情”面板。
- 先改变玩家的入关阅读与阵容判断，不改波次和数值，避免破坏已有平衡曲线。

首批落地 B：轻量关卡规则
- 每关可配置 `rules`，由 `game.js` 在敌人生成、击杀奖励、技能冷却、城池伤害等入口统一读取。
- 规则只做小幅倍率，强化关卡主题，但不重写波次。

规则类型：
- `enemySpeedMul: { type: mul }`：指定敌人速度倍率。
- `enemyHpMul: { type: mul }`：指定敌人生命倍率。
- `enemyArmorBonus: { type: n }`：指定敌人额外护甲。
- `enemyRewardMul: { type: mul }`：指定敌人击杀军粮倍率。
- `healerPowerMul`：军医治疗量倍率。
- `skillCdMul: { fire?, fort? }`：计谋冷却倍率。
- `castleDamageMul: { type: mul }`：指定敌人破城伤害倍率。

首批关卡主题规则：
- 官渡：全体击杀军粮略降，形成经济压力。
- 赤壁：火计冷却缩短，鼓励范围清场。
- 长坂坡/街亭：骑兵更快，强化控制价值。
- 定军山/火烧新野/汉中：盾兵更硬，强化破甲价值。
- 葭萌关/七擒孟获：军医治疗更强，强化点杀/范围价值。
- 陈仓：攻城车更硬且破城更痛。
- 五丈原/剑阁：Boss 与混编部队小幅增强，形成收官压力。

后续设计方向：
- 每关增加“敌情提示”：核心威胁、推荐应对、掉落提升。
- 每章至少有不同的主压力：经济、速度、护甲、治疗、Boss、混编。
- 后续可在数据层为关卡加入轻量规则，如起始军粮压力、特定敌人强化、路线压力、Boss 机制提示。

首批建议主题：
- 虎牢关：Boss 教学，集中火力。
- 官渡：军粮压力，经济型武将更有价值。
- 赤壁：范围清场，谋士更有价值。
- 长坂坡：高速骑兵，控制/射程更重要。
- 定军山：盾兵护甲，破甲/高伤更重要。
- 夷陵：持续压力，城防与稳定输出更重要。

### R25-4 人物形象升级（首批：UI 观感）

现状程序化小人适合占位，但长期游玩观感弱。资源目录中已有 5 名武将（刘备、关羽、张飞、赵云、诸葛亮）的 portrait/sheet/icons，可先用于 UI；其余武将暂用更精致的程序化头像兜底。

首批设计：
- `sprites.js` 增加 UI 头像兜底绘制：没有 portrait 的武将也显示带阵营色、兵种、星级和角色轮廓的头像，不再空白。
- 图片异步加载完成后通知 `game.js` 刷新当前武将府、选将页和招贤候选，避免首屏加载时仍显示空头像。
- 已有 portrait 优先用于武将府、选将详情、招贤候选、选将卡。

后续方向：
- 继续为 22 名武将补齐 portrait/sheet/icons。
- 战斗内小人保持可替换架构，后续逐步接入更高质量精灵表。

## 3. 实现顺序

1. R25-1 武将府合并。
2. R25-2 选将详情与兵种/定位标签。
3. 浏览器实测信息流：主界面 → 武将府 → 详情升级/招募；关卡 → 选将 → 查看详情 → 出战。
4. R25-3/R25-4 首批已落地后，后续再继续做真实关卡机制差异化与 22 将完整美术资源补齐。

## 4. 自动验证

新增 `scripts/verify-r25.js`，用于在无法进行浏览器实测时覆盖 R25 的基础回归：
- 武将府单一入口存在，旧养成/图鉴双入口不再出现在静态页面。
- 选将详情 DOM 与勾选切换逻辑存在。
- 16 关均有敌情信息，关卡 `rules` 的敌人/技能 key 合法。
- `game.js` 中敌人生命、速度、奖励、护甲、破城伤害、军医治疗、技能冷却等规则接入点存在，并抽样核对代表关卡规则值。
- 22 名武将数据存在，已有 5 名真实图片覆盖路径有效，无图武将走 `hero-fallback`。

仍需浏览器 MCP 目检的部分：
- 武将府详情升级/招募后的视觉刷新。
- 选将页敌情面板、详情面板和勾选按钮的实际布局。
- 头像兜底与真实 portrait 的视觉质量。
