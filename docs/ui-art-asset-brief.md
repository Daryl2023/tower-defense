# UI/UE 美术资产包需求与生成提示词

> 子文档，服务于后续 UI/UE 重构与素材替换。全局进度见 `../DESIGN.md`。
> 目标：先把需要向生图工具索取的素材、规格和提示词定清楚，再逐步接入游戏。

---

## 一、总体方向

当前游戏功能已经较完整，但视觉仍像“程序化占位 + 调试界面”。后续 UI/UE 重构建议从一套统一美术资产包开始，而不是零散替换单张图。

| 项 | 规格 |
|---|---|
| 主风格 | 三国国风手游塔防，Q版角色，2D 手绘，粗描边，清晰剪影，偏战棋/塔防俯视战场 |
| 角色比例 | 武将 2.5 头身；士兵 2 头身；Boss 2.8 头身或更高、更宽 |
| 画面调性 | 蜀汉主界面偏青绿/金/朱红；魏敌偏冷蓝黑/铁灰；吴敌偏赤橙/水蓝 |
| 可读性 | 角色缩小到 48px 高仍能辨认武器、头饰、阵营色 |
| 背景 | 战场背景不使用棋盘格；路径、草地、山石、水火等区域一眼可分 |
| UI | 用代码绘制主要按钮和排版；图片素材主要提供装饰框、图标、纹样、背景板 |

---

## 二、硬性技术要求

### 2.1 透明 PNG

所有角色、技能、特效、UI 装饰类素材必须满足：

```text
真透明 PNG-32，RGBA alpha 通道，背景像素 alpha=0。
禁止把透明背景画成棋盘格、灰白格、白底、灰底、纯色底、地面或场景。
禁止文字、水印、logo、签名。
```

### 2.2 精灵表分格

| 类型 | 建议尺寸 | 分格 | 用途 |
|---|---:|---|---|
| 武将战斗精灵 | 2048 x 1024 或 1024 x 512 | 2 行 x 4 列 | 待机、移动/呼吸、攻击、受击等 |
| Boss 战斗精灵 | 2048 x 1024 | 2 行 x 4 列 | 体型更大，边界留足 |
| 士兵精灵 | 1024 x 256 或 1024 x 512 | 1 行 x 4 列 或 2 行 x 4 列 | 行走、受击、死亡 |
| 技能特效 | 1024 x 1024 | 4 行 x 4 列 | 爆炸、光环、治疗、减速等帧动画 |
| 技能图标 | 256 x 256 | 单张 | UI 按钮、武将被动 |
| UI 图标 | 128 x 128 或 256 x 256 | 单张 | 军粮、城池、波次、碎片等 |

每帧角色需要完全位于自己的格子内，格子间至少留 10% 到 15% 的透明间隙，武器、披风、特效不能串到相邻帧。

## 十二、生成与验收流程

1. 先生成风格圣经，确认“角色比例、线条、饱和度、战场材质”。
2. 生成 P0 包：赵云二版、步兵/骑兵/盾兵/军医/攻城车、虎牢关战场、UI 图标样张。
3. 每张图先做透明检查：拖到深色和亮色背景上看是否有白边、灰底、棋盘格。
4. 精灵表放大检查分格：武器、披风、特效不能跨格。
5. 再交给游戏接入：先一名武将、一类敌人、一张战场、一种特效打通链路。
6. 通过后批量生成 P1/P2。

### 验收标准

| 项 | 合格标准 |
|---|---|
| 透明 | PNG 带 alpha；背景全透明；无棋盘格残留 |
| 一致 | 同一角色立绘、精灵表、图标的服装和武器一致 |
| 可读 | 48px 高度能区分武器/职业/Boss |
| 分格 | 精灵表无串帧、无贴边、脚底基本对齐 |
| 战场 | 960x600，不含角色/UI/文字，路径清楚，非棋盘格 |
| UI | 无文字，元素分散，有透明间隙，可切片 |
